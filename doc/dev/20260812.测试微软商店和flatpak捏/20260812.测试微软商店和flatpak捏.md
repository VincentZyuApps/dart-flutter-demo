### 自动发布行为

`build-release` 只创建 GitHub Release，不更新外部渠道喵。

`build-publish` 会在相同质量检查和构建成功后创建 GitHub Release、加入 `flatpak-publish-request.json`，并让独立的 `publish-microsoft-store` job 提交同一 MSIX 喵。

Flatpak 目标仓库每 15 分钟检查一次 Release 标记，也可以在 Release 成功后手动触发 `flatpak-repo` 的 `publish.yml` 立即发布喵。

Store job 使用固定版本的微软官方 App Publisher Action 与 `msstore` CLI，提交前再次核对 MSIX 文件名、大小、SHA-256、版本、x64 架构和 Package Identity 喵。

`microsoft-store-production` 不设置 required reviewer，因此 `build-publish` 不会暂停等待人工批准；推送发布 commit 前必须先检查版本和 Release Notes 喵。

如果 Store 提交失败，整次 Actions 会标红，但已创建的 GitHub Release 不会删除，Flatpak 发布请求也不会撤回喵。

后续应在 Client Secret 到期前轮换 Secret，并确保至少保留一个可用的 Entra 全局管理员账号喵。

最终目标语义如下喵。

| 触发词 | GitHub Release | Flatpak 仓库 | Microsoft Store |
|---|:---:|:---:|:---:|
| `[build-release]` | 创建 | 不更新 | 不更新 |
| `[build-publish]` | 创建 | 发布 `stable` 更新 | 上传并送审更新 |

Microsoft Store 的认证可能持续数小时或更久，因此 CI 只负责把更新提交进认证队列，不会一直占用 Runner 等待上线喵。
