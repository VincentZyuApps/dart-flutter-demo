# Windows、KDE、GNOME 桌面集成规划与进度

本文记录任务栏右键、悬停交互、系统通知和托盘右键菜单的能力边界。目标是尽量接近 Windows 11 的快捷操作体验，但不把 Linux 桌面环境未承诺的行为当作完成项。

## 2026-09-24 KDE 实测与修复

- 测试环境为 Debian 13、KDE Plasma 6.3.6、KWin Wayland，用户为 `vincentzyu`。
- beta.18 DEB 的 `/usr/share/applications/io.github.vincentzyuapps.dartflutterdemo.desktop` 已有七个 `Desktop Action`、`Actions=` 与正确的 `StartupWMClass`；面板固定项也指向同一 desktop ID。
- KDE 实际会话的 `org.mpris.MediaPlayer2.dartflutterdemo` 正在运行，`DesktopEntry` 返回 `io.github.vincentzyuapps.dartflutterdemo`，状态为 `Playing`。这证明页面到 MPRIS 的桥接本身已成功。
- 现场截图仍只显示 KWin 的窗口操作，没有 Actions 或媒体区。因此剩余问题是 Plasma 6.3 Task Manager 没把已匹配的 launcher 与动作/播放器 UI 合并，不是 DEB 缺文件或应用未发布 MPRIS。
- 已在用户会话执行 `kbuildsycoca6 --noincremental` 重建 KDE 服务缓存。重新打开右键菜单与 hover 后再验收；若仍无效，应记录为 Plasma 6.3 的呈现限制，不能承诺 Windows Jump List 式 UI。

直接执行 `/usr/bin/dart_flutter_demo` 能启动 DEB，但日常验收优先 `gtk-launch io.github.vincentzyuapps.dartflutterdemo` 或从新固定项启动，以便保留桌面启动上下文和 Wayland activation token。

## 三平台能力与目标

| 能力 | Windows 11 | KDE Plasma | GNOME |
|---|---|---|---|
| 任务栏右键入口 | Jump List，原生支持 | `.desktop` Actions，目标为运行项中显示 | `.desktop` Actions，展示位置由 Shell 决定 |
| Hover 交互 | Thumbnail Toolbar，原生支持 | MPRIS 媒体控件，关联成功后由 Task Manager 呈现 | 无官方 Dock hover 注入接口；Shell 媒体区域可使用 MPRIS |
| 上一页/下一页 | 七个快捷入口 | MPRIS 在五页间循环切换 | 同 KDE，取决于 Shell 是否显示播放器 |
| 播放/暂停 | 不使用 MPRIS | 播放或 Raise 请求恢复/置前；暂停或 Stop 请求最小化 | 同 KDE |
| 系统通知 | Windows 通知中心 | freedesktop 通知，通常右下角 | freedesktop 通知，通常屏幕上方 |
| 常驻托盘右键 | 待实现，Shell_NotifyIcon 可支持 | 待实现，StatusNotifierItem 可支持 | 待实现，通常需要 AppIndicator 扩展 |

当前页面图标就是 MPRIS 封面来源。每页使用独立 PNG 与 track ID，以避免桌面 shell 缓存上一页封面。

## Wayland 约束

Wayland 不允许后台应用无条件抢焦点。Play/Raise 会先恢复窗口并请求 `present`；若 KWin 或 GNOME Shell 拒绝置前，插件改为 urgency 提示。Pause/Stop 使用 GTK 标准最小化请求，最终状态仍由合成器决定。

Linux 没有 Windows Thumbnail Toolbar 的跨桌面等价 API。MPRIS 是媒体播放器协议，不能保证按钮一定显示在 KDE hover 或 GNOME Dock；它只保证在支持该协议的桌面媒体控件中调用同一套行为。

## KDE SSH 验收

先确认安装源并关闭旧应用：

```bash
dpkg -l | grep -i 'dart.*flutter\|flutter.*demo'
flatpak info --user io.github.vincentzyuapps.dartflutterdemo
pgrep -a -u "$(id -u)" -f 'dart_flutter_demo|dart-flutter-demo|bwrap'
```

新 DEB 的关键身份必须完全一致，并在真实 KDE session bus 中确认 MPRIS：

```bash
desktop_id=io.github.vincentzyuapps.dartflutterdemo
test -f "/usr/share/applications/$desktop_id.desktop"
grep -E '^(Exec|StartupWMClass|Actions)=' \
  "/usr/share/applications/$desktop_id.desktop"
env DBUS_SESSION_BUS_ADDRESS="unix:path=/run/user/$(id -u)/bus" \
  busctl --user get-property org.mpris.MediaPlayer2.dartflutterdemo \
  /org/mpris/MediaPlayer2 org.mpris.MediaPlayer2 DesktopEntry
gtk-launch "$desktop_id"
```

从新 launcher 启动并重新固定图标后，依次验收：启动器右键、固定图标右键、运行窗口右键、七个 Action 的页面跳转、MPRIS Previous/Next 的五页循环、当前页封面、Play/Raise 恢复窗口、Pause/Stop 最小化。KDE hover 的具体视觉位置需要截图记录；在 GNOME 则到系统媒体控件中测试相同行为。

## 后续托盘设计

常驻托盘与临时通知图标是两项功能。下一阶段使用 Windows `Shell_NotifyIcon` 和 Linux StatusNotifierItem，统一提供显示/隐藏、五页入口、About、Guide 与退出。GNOME 没有内建传统托盘，必须把 AppIndicator 扩展作为可选前提。
